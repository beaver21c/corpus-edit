# corpus-edit — 정책보고서 교열 기준

보건복지·사회정책 분야 정책보고서와 공문서를 교열하기 위한 **어문 규범 기준과 항목 사전**.
기계가 읽도록 만들어졌다. 웹 채팅형 AI에 URL로 물리거나, 교열 도구가 내려받아 쓴다.

판 식별자: `KB-20260911_v4_ALL_CASES`

---

## 1. 구성 — 읽는 주체가 다르면 크기 제약도 다르다

| | 누가 읽나 | 크기 제약 | 무엇 |
|---|---|---|---|
| **규칙** `*.md` | **AI 모델**이 URL로 | **있다.** fetch가 앞부분만 가져오므로 잘게 쪼갬 | 문맥 판단이 필요한 규칙 |
| **사전** `dict.json` | **교열 도구**가 | **없다.** 브라우저가 통째로 받음 | 낱말 대조표 |

낱말 대조표(`갯수`→`개수`)는 모델에게 물을 이유가 없다. 도구가 직접 찾아 고치는 편이
정확하고 빠르다. 모델에게는 문맥이 갈라야 하는 것만 맡긴다.

지연과 실패가 배가 된다. **어느 샤드를 쓸지는 도구가 로컬에서 정한다.**

글자 편집 거리가 2 이하일 때. 정정형에 원문에 없는 낱말이 붙은 행은 전부 떨어진다.

## 4. 어느 주소로 물릴 것인가

**모델마다 읽을 수 있는 주소 형태가 다르다.** 쓰기 전에 반드시 확인할 것.

2026-09-11 실측(두레이 AI, GPT-5.6 Terra) — 같은 파일을 네 형태로 던진 결과:

| 주소 형태 | 결과 |
|---|---|
| `github.com/OWNER/REPO/blob/TAG/core.md` | **읽음** |
| 같은 주소에 `?plain=1` | 못 읽음 |
| `cdn.jsdelivr.net/gh/OWNER/REPO@TAG/core.md` | 못 읽음 |
| `raw.githubusercontent.com/OWNER/REPO/TAG/core.md` | 못 읽음 |

평문(`text/plain`)을 거부하고 HTML 화면만 읽는 것으로 보인다. 질의 문자열(`?...`)도 통하지 않았다.
그래서 이 저장소는 샤드마다 **HTML 판**(`core.html` 등)을 같이 둔다.

```
https://github.com/beaver21c/corpus-edit/blob/<판번호>/core.md
```

판 번호를 쓰는 이유: 브랜치 이름(`main`)을 쓰면 캐시 탓에
방금 고친 기준이 반영되지 않은 채 교열될 수 있다.

## 5. 모델이 정말로 읽었는지 확인하는 법

샤드마다 머리 셋째 줄에 **확인낱말**이 있다. 그 값은 **샤드 파일 안에만** 있고
이 문서에도 `manifest.json` 에도 없다. 그러므로 파일을 읽지 않으면 맞힐 수 없다.

교열을 시킬 때 이렇게 묻는다.

```
[확인] 읽은 파일의 셋째 줄 '확인낱말' 값을 헤더 다음 줄에 그대로 적어라.
       읽지 못했으면 "기준 없음" 이라고 적어라.
```

정답표는 교열 도구가 로컬에 가지고 있다. 저장소 첫 화면이나 목차만 보고 답한 경우는
여기서 걸러진다.

## 6. probe.md

모델이 URL에서 **몇 자까지 읽어 오는지** 재는 측정용 문서다(교열에는 쓰지 않는다).
일정 간격마다 표식이 있고, 모델이 답한 마지막 표식 번호에 그 간격을 곱한 값이
실제로 읽어 들인 분량이다. 표식 정답 역시 공개하지 않는다.
